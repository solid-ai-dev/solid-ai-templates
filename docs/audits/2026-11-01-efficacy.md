We asked an AI to build the same small web app 15 times with each approach to giving it
our templates, and 15 times with no rules file at all (`none`). Each radar compares one
approach with `none`.

How to read it: the dashed ring is `none`. A point outside the ring means the approach
did better on that axis, inside it means worse. Each axis groups several measurements;
the appendix lists them.

## Each approach

Each verdict looks only at the measures chosen before the run to decide it: the hidden
tests, the security and data-protection checks, and the AI judge's scores for design,
readability, maintainability, security and data protection. One of them clearly worse
makes the verdict worse, whatever the rest gained.

### `reference`

A short file that points the AI to the templates, which it reads itself (19 lines).

- Better than no rules file at: security, design, maintainability and the tests it
  wrote.
- Worse at: reliability (3 of 15 runs passed clearly fewer of the hidden tests, 2 of
  them because the app would not start after a clean install); cost and time (about
  $7.21 a run, against $4.29 with no rules file).

**Verdict: worse**, because of the data-protection checks and the hidden tests.

### `skills`

A root file plus one skill per kind of task (1,351 lines).

- Better than no rules file at: security, data protection, design, maintainability and
  the tests it wrote.
- Worse at: cost and time (about $9.30 a run, against $4.29 with no rules file).

**Verdict: better**, on the AI judge's readability score, the AI judge's security score,
the AI judge's data-protection score and the security checks, with none of the deciding
measures worse.

### `hybrid`

The most important rules copied in, the rest pointed to (511 lines).

- Better than no rules file at: security, data protection, design, maintainability and
  the tests it wrote.
- Worse at: cost and time (about $11.78 a run, against $4.29 with no rules file).

**Verdict: better**, on the AI judge's readability score, the AI judge's data-protection
score and the security checks, with none of the deciding measures worse.

### `inline`

Every rule of the templates copied into one file (552 lines).

- Better than no rules file at: security, data protection, design, maintainability and
  the tests it wrote.
- Worse at: cost and time (about $14.18 a run, against $4.29 with no rules file).

**Verdict: better**, on the AI judge's data-protection score and the security checks,
with none of the deciding measures worse.

## The questions this round asked

- Does the skills approach do as well as the hybrid file? **Not settled: the runs could
  not tell either way.**
- Does a file that only points to the templates do worse than the hybrid file? **Yes.**
- Are the skills approach's runs at least as alike each other as the hybrid file's?
  **Yes.**

## How sure we are

- Each approach ran 15 times on one small web app, built by one AI model,
  `claude-sonnet-5`.
- Automatic tests and tools measured most of it. Another AI, `gpt-6-astra`, read the
  code and scored its design, security and tests.
- A difference counts only when it shows clearly across the runs. Small or mixed
  differences count as none.
- 9 runs were stopped part-way, for example by a usage limit, and run again from the
  start. Only complete runs count.
- 75 runs were scored in all.
